# ROS2 联调与 WSL 验证步骤

> 适用范围：
>
> - `repos/robot-onboard`
> - WSL Ubuntu 22.04
> - 原生 Ubuntu 22.04
> - 目标：先验证 `robot-ros` 与 `robot-runtime` 的建图 / 定位链路

## 一、先给结论

当前这套代码已经可以在 Linux / WSL 中验证下面这些能力：

- 导入 N10P 厂商 ROS2 驱动
- 构建 `robot-ros` 工作空间
- 启动 `robot-runtime`
- 通过 IPC 调用真实拉起：
  - `bringup`
  - `mapping`
  - `localization`
  - `navigation`
- 通过本地导航桥把目标真正发送到 Nav2 `navigate_to_pose`
- 通过 JSON 路线文件执行最小可用巡逻
- 通过 `sparkrobot_dog_bridge` 把 `cmd_vel`、狗体遥测和桥接状态一起桥接到 ROS2

当前还没有完全做完的部分：

- 导航暂停 / 恢复还没有接到 Nav2 行为树控制，目前是运行时侧“取消后重下发”
- 多地图巡逻、断点恢复、自动重试还没有做
- `sparkrobot_dog_bridge` 已补基础限幅、急停和原地转向，但还没有 gait、步态档位和更细的运控仲裁

所以这份验证手册的重点是：

1. 先把 ROS2 工作空间编译通过
2. 先把雷达、建图、定位链路跑通
3. 再补巡逻和狗体运控的高阶能力

## 二、建议环境

建议优先级：

1. 真机 Ubuntu 22.04
2. WSL Ubuntu 22.04

原因：

- 真机环境更接近最终部署
- WSL 更适合先做工作空间构建、脚本联调、接口联调
- USB 串口设备在 WSL 下还要多一层设备透传
- 网口版雷达在 WSL 下也可能受网络拓扑影响

结论：

- 如果只是先验证编译、launch、IPC，WSL 足够
- 如果要验证真实雷达数据，最终还是建议真机 Ubuntu

## 三、WSL / Ubuntu 依赖安装

以下步骤在 Ubuntu 22.04 中执行。

### 3.1 安装 ROS2 Humble

如果系统里还没有 ROS2 Humble，先安装。

至少需要这些组件：

```bash
sudo apt update
sudo apt install -y \
  ros-humble-desktop \
  python3-colcon-common-extensions \
  python3-rosdep \
  python3-vcstool \
  ros-dev-tools
```

### 3.2 初始化 rosdep

```bash
sudo rosdep init
rosdep update
```

如果你在 WSL Ubuntu 22.04 里执行 `rosdep update` 时，看到：

- 前面已经是 `Hit https://mirrors.tuna.tsinghua.edu.cn/...`
- 但后面仍然出现 `Query rosdistro index https://raw.githubusercontent.com/...`
- 最终报 `ERROR: error loading sources list`

优先看这份排障文档：

- `docs/5. WSL Ubuntu 22.04 rosdep update 失败排查.md`

### 3.3 每次新终端先 source ROS 环境

```bash
source /opt/ros/humble/setup.bash
```

如果你希望自动生效，可以自行写进 `~/.bashrc`。

## 五、先打开运行时配置

当前默认配置里，下面这些开关默认是关闭的：

- `lidar.enabled` # 网口版雷达
- `mapping.enabled` # 建图
- `localization.enabled` # 定位
- `navigation.enabled` # 导航
- `patrol.enabled` # 巡逻

所以在真正验证前，建议先编辑：

- `~/sparkrobot/config/config.toml`

至少先改成这样：

```toml
[lidar]
enabled = true
transport = "ethernet"

[mapping]
enabled = true

[localization]
enabled = true
default_map = ""

[navigation]
enabled = true

[patrol]
enabled = false
```

如果你先只测建图和定位，那么：

- `navigation.enabled = true` 可以先保留
- `patrol.enabled = false` 建议先不要开

如果你准备顺手验证巡逻，把它改成：

```toml
[patrol]
enabled = true
waypoint_dir = "/mnt/d/elric/Code/Repos/robot-system/repos/robot-onboard/examples/patrol"
```

`/sparkrobot/bridge_status` 里最值得先看的字段：

- `robot-server /api/v1/telemetry/full` 里也会出现 `bridge_status`
- `robot-runtime runtime.get_summary / runtime.get_state` 里也会带上 `dog_bridge`

```bash

  "{linear: {x: 0.05, y: 0.0, z: 0.0}, angular: {x: 0.0, y: 0.0, z: 0.0}}" \
  -r 10
```

注意：

- 先用很小速度，例如 `x=0.05`
- 周围留出安全空间
- 准备好急停
- 如果停止发送，当前狗桥会在超时后自动下发零速度

如果你想验证“原地转向策略”，可以单独发一个纯角速度命令：

预期行为：

- 机器人只做转向，不应带出明显前进线速度
- 当线速度低于 `rotate_in_place_linear_deadband` 且角速度高于 `rotate_in_place_angular_threshold` 时，桥接层会主动把 `vx / vy` 压成 `0`

```bash

```

```bash
source /opt/ros/humble/setup.bash
```

- 急停激活后，狗桥立即清空缓存速度指令并持续输出零速度
- 急停解除后，不会自动恢复到急停前的旧速度，必须重新收到新的 `cmd_vel`
- 如果 `robot-server` 遥测断流超过 `telemetry_offline_timeout_sec`，狗桥也会转入零速度输出

## 十一、当前已知限制

### 11.1 `navigation.navigate_to`

当前实现状态：

- 会确保定位栈和导航栈被拉起
- 会通过 `sparkrobot_nav_bridge` 把目标转发到 Nav2 `navigate_to_pose`
- 会把反馈状态同步回 `robot-runtime`

当前还不算最终版的部分是：

- 暂停 / 恢复还是运行时侧取消后重下发，不是 Nav2 行为树级暂停
- 还没有做自动重试和恢复策略
- 还没有做多地图巡逻和高级恢复策略

### 11.2 `patrol.start`

当前已经支持：

- 单地图 JSON 路线
- 到点等待
- `task.pause / task.resume / task.terminate`

当前限制：

- 还不支持多地图巡逻
- 路线文件必须是 JSON
- 建议先在静态地图和单楼层环境里联调

### 11.3 `sparkrobot_dog_bridge`

当前已经支持：

- `cmd_vel` 基础限幅
- `cmd_vel` 加速度斜坡限幅
- 速度指令超时自动停车
- 遥测离线自动停车
- `/sparkrobot/emergency_stop` 急停
- 基础原地转向策略
- `/sparkrobot/bridge_status` 运行状态观测

当前限制：

- 仍然是 SDK `move(vx, vy, yaw_rate)` 级别，不是正式运控总线
- 还没有 gait、姿态控制、步态档位
- 还没有做多源控制仲裁，例如遥控器、本地任务、云端接管之间的统一优先级

### 11.4 WSL 的硬件限制

如果你想在 WSL 里直接接 USB 串口版雷达，需要额外处理设备透传。

这通常意味着：

- Windows 侧先把 USB 设备共享给 WSL
- Ubuntu 里再确认 `/dev/ttyUSB*` 或自定义串口名是否存在

如果只是先验证软件链路，建议先不在 WSL 折腾串口，优先做：

- 构建
- launch
- IPC
- 地图文件加载

对 `sparkrobot_dog_bridge` 也一样：

- WSL 中通常没有智元 SDK 所需的真机环境
- 即使节点可启动，也多半只能验证 topic/TF 结构
- 真正验证 `/cmd_vel -> move(vx, vy, yaw)` 建议在机器狗本体 Ubuntu 上跑
