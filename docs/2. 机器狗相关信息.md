### 6.1.1 WebRTC/WHEP 直连（手机端默认方案）

手机端 App 使用 **WebRTC/WHEP** 协议直连机器狗获取视频流，延迟低于 RTSP/VLC。

mediamtx 在提供 RTSP 的同时，默认也会开启 WebRTC/WHEP 服务（端口 **8889**）：

| 项目           | 详情                                 |
| -------------- | ------------------------------------ |
| WHEP 端点      | `http://<robotIp>:8889/test/whep`    |
| 底层协议       | WebRTC（ICE + DTLS + SRTP）          |
| 视频编码       | H.264（mediamtx 直接转封装，无转码） |
| 延迟           | 通常 < 200ms（局域网直连）           |
| 是否需要服务器 | 否，手机与机器狗直连（同一局域网）   |

**确认 mediamtx 已启用 WebRTC** — 在机器狗上执行：

```bash
# 查看 mediamtx 配置文件（默认路径之一）
cat /etc/mediamtx/mediamtx.yml | grep -A5 webrtc
# 正常情况下应看到：
#   webrtc: yes
#   webrtcAddress: :8889

# 或直接测试 WHEP 端点
curl -i -X POST http://127.0.0.1:8889/test/whep \
  -H "Content-Type: application/sdp" -d ""
# 应返回 400（SDP 为空），说明 WHEP 服务正在运行
```

如果 WebRTC 未启用，在 `mediamtx.yml` 中添加（重启 mediamtx 后生效）：

```yaml
webrtc: yes
webrtcAddress: :8889
```

## 七、通信协议分析

> 基于 `other/dog.pcap` 抓包，时间窗约 0 ~ 35.9 s（手机 IP: 192.168.0.87，机器狗 IP: 192.168.0.85）。
> 已通过 `tools/测试数据包.py` 实机验证。

### 7.1 三通道架构

| 通道      | 协议         | 方向      | 端口                 | 用途                             |
| --------- | ------------ | --------- | -------------------- | -------------------------------- |
| 控制/心跳 | UDP          | 手机 → 狗 | 本机:8080 → 狗:8081  | 心跳 + 控制命令 + 摇杆输入       |
| 状态遥测  | UDP          | 狗 → 手机 | 狗:59755 → 本机:8080 | 高频状态推送（JSON）             |
| 视频流    | TCP/RTSP+RTP | 双向      | 手机:51144 ↔ 狗:8554 | H264 实时视频（TCP interleaved） |

### 7.2 主要流量统计

| 会话                             | 帧数      | 数据量 | 速率       |
| -------------------------------- | --------- | ------ | ---------- |
| 手机 ↔ 机器狗（总计）            | 21,623 帧 | ~20 MB | —          |
| 狗:59755 → 手机:8080（状态遥测） | 6,965 包  | —      | ~225 包/秒 |
| 手机:8080 → 狗:8081（控制/心跳） | 1,477 包  | —      | ~51 包/秒  |

### 7.3 交互时序

| 时间点   | 事件                                             |
| -------- | ------------------------------------------------ |
| ~4.919 s | 手机开始发 UDP 心跳（8080 → 8081）               |
| ~4.949 s | 机器狗开始 UDP 状态推送（59755 → 8080）          |
| ~7.489 s | 手机发送 RTSP OPTIONS                            |
| ~7.495 s | DESCRIBE 返回 SDP，声明 `a=rtpmap:96 H264/90000` |
| ~7.502 s | SETUP 使用 `RTP/AVP/TCP;interleaved=0-1`         |
| ~7.508 s | PLAY 后开始高频 RTP 视频流                       |

### 8.2 摇杆控制 (Joystick) (未验证)

摇杆数据包含 4 个轴 `[Axis 0, Axis 1, Axis 2, Axis 3]`。

#### 左摇杆 (Left Stick) - 主要控制平面移动

- **Axis 0 (左右平移)**
  - 负值 (-): **向左**
  - 正值 (+): **向右**
- **Axis 1 (前后移动)**
  - 负值 (-): **向前** (推杆)
  - 正值 (+): **向后** (拉杆)
    _(注：符合常见手柄逻辑，推杆数值减小)_

#### 右摇杆 (Right Stick) - 主要控制旋转与姿态

- **Axis 2 (旋转/偏航)**
  - 负值 (-): **左转**
  - 正值 (+): **右转**
- **Axis 3 (垂直/俯仰)**
  - _仅在姿态模式或特定动作下生效_
  - 负值 (-): **向上** (抬头/升高)
  - 正值 (+): **向下** (低头/降低)
