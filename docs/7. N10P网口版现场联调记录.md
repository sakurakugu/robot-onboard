## 零、额外更新（2026-04-24）

> 时间：2026-04-24
>
> 目标机器狗：`192.168.1.108`，狗69

这份文档记录的是当时把默认雷达网段 `192.168.1.x` 直接接入机器狗的现场过程。

后续又确认了一个新坑：

1. 如果机器狗 `wlan0` 也在 `192.168.1.x`
2. 再给 `eth0` 挂 `192.168.1.102/24`

那么同一台机器上的 `wlan0` 和 `eth0` 会同时落在 `192.168.1.0/24`，这会导致路由歧义，常见现象就是 SSH 直接失联。

所以当前推荐方案已经改为：

```toml
[lidar]
device_ip = "192.168.168.200"
host_ip = "192.168.168.168"
msop_port = 2368
difop_port = 2369
```

对应网络建议为：

- `wlan0`：继续走现场 Wi-Fi，例如 `192.168.1.x`
- `eth0`：固定 `192.168.168.168/24`
- 雷达：改为 `192.168.168.200`
- 雷达数据目标 IP：改为 `192.168.168.168`
- 雷达网关：留空（或保持原样）

雷达的修改在 官方的上位机中可以修改
![](.\图片\如何修改雷达IP.png)

下面原文保留，作为当时旧方案的现场记录。

## 一、这次已经确认的结论

也就是说，下面这些配置现在都会真正传给 `lslidar_driver`：

- `lidar.serial_port`

- `lidar.host_ip`
- `lidar.msop_port`
- `lidar.difop_port`
- `lidar.frame_id`
- `lidar.angle_disable_min`
- `lidar.angle_disable_max`
- `lidar.min_range`
- `lidar.max_range`

运行时生成文件路径为：

- `/home/firefly/sparkrobot/config/generated/ros/lidar_runtime_ethernet.yaml`
- `/home/firefly/sparkrobot/config/generated/ros/lidar_runtime_serial.yaml`

## 二、这次现场真正卡住的原因

不是 ROS2 没起来，也不是 `robot-runtime` 没拉起建图。

真正原因是：

1. 网口版 N10P 当前仍然是厂商默认网段
2. 雷达默认 IP 是 `192.168.1.200`
3. 主机接收 IP 需要在同网段，现场验证使用的是 `192.168.1.102`
4. 机器狗当前 `eth0` 原本只有 `192.168.168.168/24`
5. 所以前面虽然已经切到 `ethernet`，但因为网段不对，驱动发给雷达的启动命令到不了，`/scan` 也就没有数据

## 三、这次现场验证到的有效配置

当前远端 `config.toml` 里，已经改为：

```toml
[lidar]
enabled = true
transport = "ethernet"
device_model = "n10p"
device_ip = "192.168.1.200"
host_ip = "192.168.1.102"
msop_port = 2368
difop_port = 2369
frame_id = "laser"
```

现场为了不破坏原本 `eth0` 的 `192.168.168.168/24`，额外给 `eth0` 挂了一个临时别名：

```bash
sudo ip addr add 192.168.1.102/24 dev eth0
```

这样 `eth0` 上同时存在：

- `192.168.168.168/24`
- `192.168.1.102/24`

## 五、当前需要记住的坑

### 5.1 `eth0` 的第二地址已经持久化

现场后续已经把 `192.168.1.102/24` 正式写进 `NetworkManager` 的 `eth0` 连接配置。

当前远端配置文件为：

```ini
/etc/NetworkManager/system-connections/eth0.nmconnection
```

其中关键段落已经变成：

```ini
[ipv4]
address1=192.168.168.168/24
address2=192.168.1.102/24
method=manual
```

也就是说，当前不是只靠临时命令保活，而是已经做成了持久配置。

这次现场采用的持久化命令是：

```bash
sudo nmcli connection modify eth0 +ipv4.addresses 192.168.1.102/24
sudo nmcli connection reload
sudo nmcli device reapply eth0
```

所以正常情况下，机器狗重启后 `eth0` 也应该继续保留：

- `192.168.168.168/24`
- `192.168.1.102/24`

### 5.2 当前不要再把 `host_ip` 改回 `192.168.168.168`

对于这台现场雷达，当前已经确认有效的是：

- `device_ip = 192.168.1.200`
- `host_ip = 192.168.1.102`

所以在没有改雷达 IP 之前，不要把它改回：

- `host_ip = 192.168.168.168`

否则又会回到“驱动能起，但收不到扫描”的状态。

### 5.3 `ros2 topic echo /scan` 现场有一个额外 CLI 问题

这台机器上直接跑：

```bash
ros2 topic echo --once /scan
```

现场遇到过：

- `RuntimeError: logger with name 'root' already exists`

这不是雷达没数据，而是当前 ROS CLI / 日志环境里还有一个单独问题。

所以现场更稳的确认方式是：

1. 先抓 `tcpdump`
2. 再用最小 `rclpy` 订阅脚本确认 `/scan`
