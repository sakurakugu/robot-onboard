# 本体一键打包与安装说明

> 适用范围：
>
> - `repos/robot-onboard`
> - `tools/1.常用命令.py`
> - 目标机器狗 Ubuntu
> - WSL Ubuntu 22.04 联调环境

## 一、这次已经具备的能力

当前 `tools/1.常用命令.py` 已支持下面两类能力：

- 本地一键打包本体全套
- 连接目标机器狗后，一键打包并安装本体全套

当前纳入范围的项目：

- `sparkrobot-common`
- `robot-server`
- `robot-agent`
- `robot-runtime`
- `robot-ros`

其中：

- `robot-server`
- `robot-agent`
- `robot-runtime`

会被安装成 systemd 服务。

- `robot-ros`

会被当作 ROS2 工作区部署，并在目标机器上执行：

```bash
rosdep init
rosdep update
rosdep install --from-paths src --ignore-src -r -y
colcon build
```

补充说明：

- 如果目标机还没初始化 `rosdep`，安装脚本会先尝试自动执行 `rosdep init`
- `rosdep update` 当前会优先切到 TUNA 源，减少直连 GitHub 超时问题

## 二、服务名约定

为避免和系统已有服务重名，当前统一使用 `sparkrobot-` 前缀。

当前服务名为：

- `sparkrobot-server.service`
- `sparkrobot-agent.service`
- `sparkrobot-runtime.service`

所以后续查看状态、重启、拉日志时，统一使用这些名字。

示例：

```bash
sudo systemctl status sparkrobot-server.service
sudo systemctl status sparkrobot-agent.service
sudo systemctl status sparkrobot-runtime.service
sudo journalctl -u sparkrobot-runtime.service -f
```

## 三、如何使用工具脚本

在 Windows 仓库根目录下执行：

```bash
cd D:\elric\Code\Repos\robot-system\repos\robot-onboard
python tools\1.常用命令.py
```

主菜单里现在有两个相关入口：

- `6) 安装机器狗软件`
- `7) 打包本体软件`

### 3.0 命令行模式

除了交互菜单，现在也支持直接通过 `--xxx` 执行。

常见示例：

```bash
python tools\1.常用命令.py --package full --format zip
python tools\1.常用命令.py --install full --robot-ip 192.168.1.106
python tools\1.常用命令.py --install ros --robot-ip 192.168.1.106
python tools\1.常用命令.py --robot-ip 192.168.1.106 --robot-port 43988 --save-target
```

当前主要参数：

- `--robot-ip`
- `--robot-port`
- `--save-target`
- `--install common|server|agent|runtime|ros|full`
- `--package common|server|agent|runtime|ros|full`
- `--format tar.gz|zip|tar|tar.bz2|tar.xz`

说明：

- `--install` 和 `--package` 不能同时使用
- 如果没有传 `--robot-ip`，会尝试读取已保存的默认目标

### 3.1 本地打包

进入：

- `7) 打包本体软件`

可选：

- 一键打包本体全套
- 单独打包 `sparkrobot-common`
- 单独打包 `robot-server`
- 单独打包 `robot-agent`
- 单独打包 `robot-runtime`
- 单独打包 `robot-ros`

打包产物默认输出到：

- `repos/robot-onboard/dist/packages/`

### 3.2 远程安装

进入：

- `6) 安装机器狗软件`

先设置目标机器狗 IP 和端口，然后可选：

- 安装 `sparkrobot-common`
- 安装 `robot-server`
- 安装 `robot-agent`
- 安装 `robot-runtime`
- 安装 `robot-ros` 工作区
- 一键打包并安装本体全套

这里的“安装”不是直接用本地源码远程跑，而是：

1. 先在本地打包当前代码
2. 上传到目标机器狗 `/home/firefly/sparkrobot/packages/`
3. 解压到对应目录
4. 执行 pip 安装 / install.sh / ROS2 构建

## 四、一键安装本体全套时实际顺序

当前“一键打包并安装本体全套”执行顺序如下：

1. 安装 `sparkrobot-common`
2. 安装 `robot-server`
3. 安装 `robot-agent`
4. 安装 `robot-ros`
5. 安装 `robot-runtime`

对应的目标目录为：

- `/home/firefly/sparkrobot/sparkrobot-common`
- `/home/firefly/sparkrobot/robot-server`
- `/home/firefly/sparkrobot/robot-agent`
- `/home/firefly/sparkrobot/robot-ros`
- `/home/firefly/sparkrobot/robot-runtime`

这样安排的原因是：

- `robot-agent` 依赖 `robot-server`
- `robot-runtime` 真正跑建图、定位、导航前，需要 `robot-ros` 工作区先构建好

## 五、目标机器的前置条件

### 5.1 通用前置条件

目标机器狗上至少需要：

- Ubuntu
- `python3`
- `pip`
- `systemd`
- 可用的 `sudo`
- 用户 `firefly`

### 5.2 `robot-ros` 的额外前置条件

如果要安装 `robot-ros`，目标机器上还需要：

- ROS2 Humble
- `rosdep`
- `colcon`
- 可正常使用 `sudo`
- 目标机能联网完成 `rosdep update`

如果这些前置条件不满足，那么：

- 单独安装 `robot-server`
- 单独安装 `robot-agent`
- 单独安装 `robot-runtime`

可能还能成功，但：

- `robot-runtime` 的建图、定位、导航链路无法真正工作

## 六、厂商雷达驱动的前置条件

`robot-ros` 当前不会自动从 `other/2D激光雷达资料/` 远程拷厂商驱动。

所以在执行“安装 `robot-ros`”或“一键安装本体全套”前，建议先在本地仓库执行：

```bash
cd D:\elric\Code\Repos\robot-system\repos\robot-onboard
python tools\scripts\robot\import_lslidar_driver.py
```

执行后，确认下面两个目录已经进入：

- `robot-ros/src/lslidar_driver`
- `robot-ros/src/lslidar_msgs`

否则远程 `rosdep install` 或 `colcon build` 很可能失败。

## 七、WSL 的建议定位

如果你要先在 Linux 环境里验证：

- ROS2 是否能装通
- `robot-ros` 是否能编译
- `robot-runtime` 是否能正常发现工作区

可以优先用：

- WSL Ubuntu 22.04

推荐用途：

- `rosdep install`
- `colcon build`
- launch 联调
- IPC 联调

不推荐直接把 WSL 当最终真机环境来验证：

- USB 串口版雷达需要额外设备透传
- 网口版雷达也可能受到 WSL 网络拓扑影响
- 智元 SDK / 真机遥测链路在 WSL 里通常不完整

更详细的 WSL 步骤可参考：

- `docs/4. ROS2联调与WSL验证步骤.md`
- `docs/5. WSL Ubuntu 22.04 rosdep update 失败排查.md`

## 八、安装完成后的自检命令

### 8.1 检查服务状态

```bash
sudo systemctl status sparkrobot-server.service
sudo systemctl status sparkrobot-agent.service
sudo systemctl status sparkrobot-runtime.service
```

### 8.2 检查 `robot-ros` 是否构建完成

```bash
ls /home/firefly/sparkrobot/robot-ros/install/setup.bash
```

如果这个文件不存在，说明：

- `robot-ros` 的远程构建还没成功

### 8.3 检查运行时日志

```bash
sudo journalctl -u sparkrobot-runtime.service -n 100 --no-pager
```

如果运行时启动成功，通常会看到：

- ROS 工作空间摘要
- `vendor_driver_ready`
- `install_setup_ready`
- `ROS 雷达参数摘要`

### 8.4 检查运行时生成的雷达参数文件

```bash
ls /home/firefly/sparkrobot/config/generated/ros/
cat /home/firefly/sparkrobot/config/generated/ros/lidar_runtime_ethernet.yaml
```

说明：

- `robot-runtime` 现在会根据 `/home/firefly/sparkrobot/config/config.toml` 动态生成雷达参数文件
- `lidar.transport / serial_port / device_ip / host_ip / msop_port / difop_port / frame_id / angle_disable_min / angle_disable_max / min_range / max_range` 都会写进去
- 不再只是二选一引用 `robot-ros/src/sparkrobot_bringup/config/` 里的静态模板

## 九、目前这套一键安装的边界

当前已解决：

- 本地打包入口统一
- `robot-runtime` 已纳入打包与安装
- `robot-ros` 已纳入部署与构建
- 服务名冲突已改为 `sparkrobot-*`

当前仍然不自动处理的部分：

- 目标机器的 ROS2 Humble 安装
- 厂商驱动从资料目录自动导入到本地仓库
- 雷达真机接线、真实设备 IP、主机网卡 IP、网段对齐
- 地图文件准备与 9.4 之后的地图加载业务验证

当前虽然会自动尝试处理：

- `rosdep init`
- `rosdep update`

但如果目标机网络、DNS、镜像源异常，仍然需要人工排查。

所以最稳的落地顺序仍然是：

1. 先在本地导入 `lslidar_driver / lslidar_msgs`
2. 先在 WSL 或 Ubuntu 22.04 验证 `robot-ros` 能编译
3. 再对目标机器执行“一键打包并安装本体全套”
4. 最后验证地图加载、定位、导航、巡逻
