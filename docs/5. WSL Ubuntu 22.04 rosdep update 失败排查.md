# WSL Ubuntu 22.04 `rosdep update` 失败排查

> 适用范围：
>
> - `repos/robot-onboard/robot-ros`
> - WSL Ubuntu 22.04
> - ROS2 Humble
> - 典型现象：`rosdep update` 在查询 rosdistro 索引时失败

## 一、先给结论

即使你已经把 `rosdep` 的 yaml 源切到了清华镜像，`rosdep update` 仍然可能继续访问：

```text
https://raw.githubusercontent.com/ros/rosdistro/master/index-v4.yaml
```

在部分 WSL Ubuntu 22.04 环境里，这一步会超时，最终报：

```text
ERROR: error loading sources list:
```

最快的解决方式不是重装 `rosdep`，而是把 `ROSDISTRO_INDEX_URL` 明确切到清华镜像。

## 二、现场特征

如果你看到类似输出，基本就是这个问题：

```text
Hit https://mirrors.tuna.tsinghua.edu.cn/rosdistro/rosdep/base.yaml
Hit https://mirrors.tuna.tsinghua.edu.cn/rosdistro/rosdep/python.yaml
Hit https://mirrors.tuna.tsinghua.edu.cn/rosdistro/rosdep/ruby.yaml
Query rosdistro index https://raw.githubusercontent.com/ros/rosdistro/master/index-v4.yaml
ERROR: error loading sources list:
```

补充说明：

- 前面的 `Hit https://mirrors.tuna.tsinghua.edu.cn/...` 只能说明 `rosdep` 的规则文件在走镜像
- 真正失败的是 rosdistro 总索引仍然走了 GitHub 原始地址
- `/usr/bin/rosdep:6: UserWarning: pkg_resources is deprecated as an API` 只是警告，不是这次故障的根因

## 三、临时修复

如果你只是想先把当前环境跑通，直接执行：

```bash
ROSDISTRO_INDEX_URL=https://mirrors.tuna.tsinghua.edu.cn/rosdistro/index-v4.yaml rosdep update
```

如果成功，输出里应出现：

```text
Query rosdistro index https://mirrors.tuna.tsinghua.edu.cn/rosdistro/index-v4.yaml
updated cache in /home/<你的用户名>/.ros/rosdep/sources.cache
```

## 四、推荐的持久化修复

如果你之后还会继续在这套 WSL 里做 ROS2 开发，建议直接放一个包装脚本到 `/usr/local/bin/rosdep`。

这样做的好处是：

- 不改系统包自带的 `/usr/bin/rosdep`
- 不依赖 `~/.bashrc`、`~/.profile` 是否被当前 shell 正确加载
- 以后直接敲 `rosdep update` 就能生效

执行：

```bash
sudo tee /usr/local/bin/rosdep >/dev/null <<'EOF'
#!/usr/bin/env bash
export ROSDISTRO_INDEX_URL=https://mirrors.tuna.tsinghua.edu.cn/rosdistro/index-v4.yaml
exec /usr/bin/rosdep "$@"
EOF

sudo chmod 755 /usr/local/bin/rosdep
```

然后验证：

```bash
which rosdep
rosdep update
```

预期结果：

- `which rosdep` 输出 `/usr/local/bin/rosdep`
- `rosdep update` 中的 `Query rosdistro index` 指向清华镜像
- 最终出现 `updated cache in .../.ros/rosdep/sources.cache`

## 五、回滚方式

如果以后你不想保留这个包装脚本，可以回滚：

```bash
sudo rm -f /usr/local/bin/rosdep
which rosdep
```

回滚后，`which rosdep` 应重新指向 `/usr/bin/rosdep`。

## 六、建议的排障顺序

下次再遇到同类问题，按这个顺序排即可：

1. 先看 `rosdep update` 是否卡在 `Query rosdistro index https://raw.githubusercontent.com/...`
2. 如果是，先用临时命令验证：

```bash
ROSDISTRO_INDEX_URL=https://mirrors.tuna.tsinghua.edu.cn/rosdistro/index-v4.yaml rosdep update
```

3. 临时命令成功后，再决定是否写入 `/usr/local/bin/rosdep`
4. 不要因为这个问题去重装整套 ROS2，通常没有必要

## 七、和当前仓库的关系

本仓库里 `robot-ros` 的依赖安装步骤依赖：

```bash
rosdep install --from-paths src --ignore-src -r -y
```

而这一步默认要求前面已经成功执行过：

```bash
rosdep update
```

所以如果你在 `robot-ros` 的依赖安装阶段卡住，优先先排查这里。
